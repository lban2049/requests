# 更新日志

本页面详细记录了 Requests 库每个版本的全部变更、改进和错误修复。如需了解最新的、正在开发中的变更，请参阅 `dev` 部分。

## dev (未发布)

### 弃用
- 增加了对 Python 3.14 的支持。
- 鉴于 Python 3.8 支持已终止，取消了对其的支持。

## 2.32.4 (2025-06-10)

### 安全性
- **CVE-2024-47081**：修复了一个问题，即在受信任的环境中，恶意构造的 URL 会从 netrc 文件中检索到错误的主机名/机器的凭据。

### 改进
- 大量文档改进。

### 弃用
- 增加了对适用于 Linux 和 macOS 的 PyPy 3.11 的支持。
- 鉴于 PyPy 3.9 支持已终止，取消了对其的支持。

## 2.32.3 (2024-05-29)

### 错误修复
- 修复了一个错误，该错误导致无法在 `HTTPAdapter` 的子类中指定自定义 `SSLContexts`。(#6716)
- 修复了一个问题，该问题导致 Requests 在没有 `ssl` 模块的情况下编译的 Python 版本上无法运行。(#6724)

## 2.32.2 (2024-05-21)

### 弃用
- 为了给受 2.32.0 版本中 CVE 变更影响的自定义 `HTTPAdapters` 提供更稳定的迁移路径，我们将 `_get_connection` 重命名为一个新的公共 API `get_connection_with_tls_context`。现有的自定义 `HTTPAdapters` 需要迁移其代码以使用此新 API。在所有 Requests >= 2.32.0 的版本中，`get_connection` 均被视为已弃用。

## 2.32.1 (2024-05-20)

### 错误修复
- 在 PyPI 上分发的 sdist 中添加了缺失的测试证书。

## 2.32.0 (2024-05-20)

### 安全性
- 修复了一个问题，即在 Session 的第一个请求中设置 `verify=False` 会导致后续对同一来源的请求也忽略证书验证，无论 `verify` 的值如何。([GHSA-9wx4-h78v-vm56](https://github.com/psf/requests/security/advisories/GHSA-9wx4-h78v-vm56))

### 改进
- `verify=True` 现在会复用一个全局的 `SSLContext`，这应能改善首次请求与后续请求之间的时间差异。当使用基于 OpenSSL 3.x 构建的 Python 版本时，此举还应能最大限度地减少 Windows 系统上的证书加载时间。(#6667)
- Requests 现在支持可选地使用字符检测库（`chardet` 或 `charset_normalizer`）。如果这两个库都不存在，`Response.text()` 和 `apparent_encoding` API 将默认使用 `utf-8`。(#6702)

### 错误修复
- 修复了一个错误，该错误导致请求的 content-length 中表情符号的长度计算不正确。(#6589)
- 修复了 `JSONDecodeError` 中的一个反序列化错误。(#6629)
- 修复了一个错误，即额外的前导 `/` 可能导致 `urllib3` 不必要地重新解析请求 URI。(#6644)

### 弃用
- 增加了对 CPython 3.12 的官方支持。(#6503)
- 增加了对 PyPy 3.9 和 3.10 的官方支持。(#6641)
- 取消了对 CPython 3.7 的官方支持。(#6642)
- 取消了对 PyPy 3.7 和 3.8 的官方支持。(#6641)

### 打包
- 项目的源文件现在位于 sdist 的 `src/requests` 目录中。(#6506)
- 从 Requests 2.33.0 开始，构建系统将使用 `hatchling` 迁移到 PEP 517。

## 2.31.0 (2023-05-22)

### 安全性
- **CVE-2023-32681**：修复了一个漏洞，该漏洞可能导致在遵循 HTTPS 重定向时，`Proxy-Authorization` 标头被转发到目标服务器。强烈建议在 URL 中定义代理凭据的用户进行升级。详情请参阅完整的 [GitHub 安全公告](https://github.com/psf/requests/security/advisories/GHSA-j8r2-6x86-q33q)。

## 2.30.0 (2023-05-03)

### 依赖项
- 增加了对 `urllib3` 2.0 的支持。这可能包含一些小的破坏性变更。用户可以将版本固定在 `urllib3<2` 以继续使用 1.x 系列。

## 2.29.0 (2023-04-26)

### 改进
- 将分块请求推迟到 `urllib3` 实现，以提高标准化程度。(#6226)
- 放宽了标头组件的要求，以支持 bytes/str 子类。(#6356)

## 2.28.2 (2023-01-12)

### 依赖项
- Requests 现在支持 `charset_normalizer` 3.x。(#6261)

### 错误修复
- 更新了 `MissingSchema` 异常，建议使用 `https` 协议而不是 `http`。(#6188)

## 2.28.1 (2022-06-29)

### 改进
- 通过过渡到 `yield from` 优化了 `iter_content`。(#6170)

### 依赖项
- 增加了对 `chardet` 5.0.0 的支持。(#6179)
- 增加了对 `charset-normalizer` 2.1.0 的支持。(#6169)

## 2.28.0 (2022-06-09)

### 弃用
- **取消了对 Python 2.7 的支持。**
- 取消了对 Python 3.6 (包括 pypy3.6) 的支持。

### 改进
- 对于没有编码的有效负载，将 JSON 解析问题包装在 `requests.JSONDecodeError` 中，以使 `json()` API 保持一致。(#6097)
- 增加了对 Python 3.11 的临时支持。

### 错误修复
- 修复了将 `CURL_CA_BUNDLE` 设置为空字符串会禁用证书验证的错误。(#6074)
- 修复了一个问题，即无效的 Windows 注册表项导致代理解析引发异常。(#6149)

## 2.27.1 (2022-01-05)

### 错误修复
- 修复了一个解析问题，该问题导致代理 URL 中的 `auth` 组件被丢弃。(#6028)

... 以此类推，适用于所有以前的版本。
